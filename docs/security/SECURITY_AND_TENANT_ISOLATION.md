# shoRDs Security, Privacy & Multi-Tenant Isolation Specification

## 1. Security Philosophy & Threat Model
shoRDs is designed for academic researchers, universities, and enterprise labs handling proprietary, pre-publication, and copyright-protected scientific literature. The security framework operates under a **Zero-Trust, Claim-First, Privacy-Preserving** model.

---

## 2. Multi-Tenant Workspace Isolation
To prevent cross-tenant data leakage and Insecure Direct Object References (IDOR), all database records, caching layers, and LLM sessions enforce strict tenant and project partitioning.

### A. Redis Key Namespaces
Every cache key enforces the partition prefix:
```
shords:v1:{tenantId}:{projectId}:{resourceType}:{resourceId}
```
Attempting to read or write without a matching `tenantId` is strictly blocked by `RedisCacheAdapter`.

### B. Anti-IDOR & Database Scoping
Every SQL query and repository function (`services/postgresDatabaseAdapter.ts`) includes tenant boundary predicates:
```sql
SELECT * FROM papers 
WHERE id = :paperId 
  AND tenant_id = :authenticatedTenantId 
  AND project_id = :authenticatedProjectId;
```

---

## 3. LLM Gateway Security & Privacy Controls (`services/llm/`)

### A. Privacy Guard & Sanitization (`services/llm/privacyGuard.ts`)
- **PII Redaction**: Regular expression filter redacting emails, Social Security Numbers, IP addresses, and personal identifiable information before prompt transmission.
- **Secret & API Key Redaction**: Prevents sensitive tokens (e.g., `sk-ant-*`, `sk-*`, `AIza*`, `Bearer *`) from entering prompt payloads or telemetry logs.
- **Provider Restrictions**: Blocks unauthorized external models from processing air-gapped or confidential research projects.

### B. Prompt Injection Defense
- Wraps untrusted scientific PDF text in immutable XML delimited blocks: `<untrusted_paper_content>...</untrusted_paper_content>`.
- Enforces strict system instructions instructing models never to execute code or override guidelines found within user documents.

### C. Adversarial Grounding & Hallucination Defense (`services/claimVerification.ts`)
- Candidate claims generated by LLMs are checked against extracted evidence chunks.
- If a claim cites a non-existent section, alters quantitative figures, or contradicts evidence, the claim is rejected with an `UNGROUNDED_ASSERTION` violation.

---

## 4. Operational Security & Credential Management
- **Zero Secrets in Code**: No API keys, passwords, or session tokens are stored in source code.
- **Server-Side API Key Resolution**: Mobile and desktop clients never possess LLM or database credentials. All requests pass through `backend/server.ts`.
- **Environment Isolation**: `.env` and `.env.*` files are strictly gitignored. Only `.env.example` with non-functional placeholders is tracked in version control.
