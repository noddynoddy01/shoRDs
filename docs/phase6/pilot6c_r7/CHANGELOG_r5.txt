WHY r5 EXISTS
  Dry Run A of r4 stopped at once with:
    The variable cannot be validated because the value 0 is not a valid value for the Ctx variable. (ValidateSetFailure, Invoke-PilotRun.ps1)
  Root cause (confirmed): Invoke-PilotRun.ps1 declared the script parameter  [ValidateSet(4096, 8192, 12288)][int]$Ctx = 4096 . A script parameter is a
  variable in SCRIPT scope and keeps its type and validation attributes. The script then dot-sources Phase6C.Runtime.ps1, which runs in the same scope
  and executes  $script:Ctx = $null  (the pilot-context variable). PowerShell variable names are case-insensitive and  $script:Ctx  IS  $Ctx , so the
  assignment re-assigned the parameter; $null converts to 0 for [int], and ValidateSet(4096, ...) refuses 0. Nothing else in Dry Run A had run yet
  (no folder, file, process or request). The same variable was also needed for the pilot context hashtable, so renaming the script-scope object would
  have been wrong; the parameter had to change.
  Why every earlier check missed it: Test-AgentLogic.ps1 dot-sources only Phase6C.Lib.ps1, never the orchestrator; the Python mirror tests and the static
  analyser compared names inside one file or treated every $script: name as "defined"; no real PowerShell was available to the author.

SECOND DEFECT FOUND BY THE AUDIT (not reported by you; safety relevant)
  [ValidateSet('DryRun','Live')] ignores case and KEEPS the typed spelling. With  -Mode live  the orchestrator's  $Mode -ceq 'Live'  was false (so it showed
  the DRY RUN approval and asked for APPROVE E-DRYRUN) while the handlers test  $script:Ctx.Mode -ceq 'DryRun'  which was also false (so they took the LIVE branch).
  r5 normalises the spelling in both entry scripts before first use (-Mode live/LIVE/Live -> Live; dryrun/DRYRUN -> DryRun) and Initialize-PilotContext refuses any
  other value. No gate was loosened; this closes a path in which the wrong approval phrase could be accepted.
