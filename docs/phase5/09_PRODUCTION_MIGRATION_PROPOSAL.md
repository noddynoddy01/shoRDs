# 14. Production migration proposal (Stages 5A to 5E)

Date 2026-11-04 · **Status: PROPOSED. Nothing here is implemented in production code, nothing is wired in, the default stays Claude, and no stage starts without your approval.** The only changes in the working copy are additive files under `backend/native/`, `backend/eval/`, `scripts/`, tests and docs, plus one commented allow-list line in `aiBudget.test.js`.

## 9.1 Principle

Replace the *dependency*, not the *safeguards*. Every stage keeps: the licence gate, the spend gate, the claim guard, the production validator, the "no raw model output to users" rule, and Claude as a controlled fallback. A stage is entered only when the previous stage's exit test passes. The default model is not switched in any stage below except 5E, which is a separate decision.

## 9.3 Stage 5B in detail: the integration work

These are the places that currently say "Claude" and must become provider-neutral. File names are from the Phase 5 dependency map (`01_…`).

1. **Result vocabulary.** `modelMode === "EXTERNAL_CLAUDE"` (in `resultCache.isRealCompleteAnswer`, `intelligence.js`, `copilotService.js`, `usageLedger`, frontend labels) becomes a neutral set: `EXTERNAL_MODEL`, `NATIVE_MODEL`, with `provider` and `model` stored separately. This changes cache identity: bump the cache/prompt version and treat old rows as readable-but-expired. A migration must be additive (new column or JSON field, default from the old value); no destructive migration.
2. **Price table per model.** `aiBudget.PRICING_PER_MTOK` currently prices Claude models and offers one global override. Add per-model entries (an operator sets a native model's price; an unpriced model stays denied: the current behaviour is correct and should be kept). Self-hosted: price set to the amortised GPU cost per token, decided by you.
3. **Per-provider breaker and kill switch.** The breaker key `shords:ai:breaker:v1:anthropic` becomes `…:v1:<provider>`; the kill switch keeps a global switch and gains per-provider switches, so turning off the native path cannot turn off Claude and vice versa.
4. **Native model behind the same gate.** The native adapter is passed through `guardClient` (as Claude is). Its `withSpendLimit` is then redundant for production but stays for local runs. For a self-hosted model the per-request ceiling still applies (it protects against runaway prompts).
5. **Readiness probe.** `readiness.js` probes Claude. Add a probe per configured provider; `health` reports each, never a key.
6. **Router.** Use `createRouter` in the gateway: order native → Claude fallback, or Claude → native in shadow mode. A policy refusal is never retried on a paid provider (already tested).
7. **Document intelligence service.** The extractor currently handles JATS/HTML only. Choose a PDF extractor (D-5-3; candidates in `04_…`: poppler `pdftotext` as a separate process for plain text, or a layout-aware tool such as GROBID/Docling for sections and tables, whose licence and maintenance need review) and run it as a separate worker, not inside the web process (CPU, memory, untrusted input).
8. **Evidence UI.** The frontend already shows citations (`AnalysisPanel`). The native result carries `evidence[]` with chunk ids and verbatim quotes in the same spirit; mapping it to the existing evidence view is small, and the "automatic checks, not proof" note must be shown with it.
9. **Config.** New env names (not secrets): `NATIVE_ENGINE_ENABLED` (default off), `NATIVE_MODEL_BASE_URL`, `NATIVE_MODEL_NAME`, `NATIVE_MODEL_PRICE_*`. No change to `ANTHROPIC_*`. I did not and will not set anything in Railway or Vercel.
10. **Fix the guard gaps F-5-1/F-5-2** (see `08_…`) *before* 5C, with a prompt-version bump.

## 9.4 Rollback

Every stage is reversible by a flag: `NATIVE_ENGINE_ENABLED=false` returns all traffic to the current path; stored native rows are in separate storage and can be dropped without touching existing data. The cache identity change in 5B is the only step that is not a pure flag; it is why it is staged and reviewed on its own.

## 9.5 What Claude is still used for

Fallback when the native engine fails or flags its own output, escalation for hard papers, the baseline arm of every future evaluation, and, until the evaluation says otherwise, the default. The engine is designed so that the day Claude is removed, nothing else has to change; the day it is wanted again, nothing has to be rebuilt.

## 9.6 Risks of the migration itself

| Risk | Mitigation |
|---|---|
| A cheaper model writes plausible but wrong summaries | decision rule includes factual/quantitative non-inferiority and an unsafe-rate limit; guard and cited quotes shown; shadow mode before any user sees it |
| Quality differs by field of science | per-category results are in the report; native may be enabled for categories where it passes |
| Hosted provider changes price/terms | prices are config, not code; evaluation re-run on any model change |
| Self-hosting operations burden | not recommended at current volume (`06_…`) |
| Cache poisoning across providers | cache key includes provider, model and prompt version (extend per 9.3.1) |
| Scope creep | each stage ends with a report and your decision |
